# Linux SRE Lab

A hands-on learning repository documenting my journey towards becoming a Site Reliability Engineer (SRE).

The goal is to understand Linux from the ground up, develop practical system administration skills, and learn how to operate, troubleshoot and maintain Linux infrastructure in real-world environments.

## Objectives

- Understand Linux architecture, kernel and user space.
- Become confident with the Linux command line and filesystem.
- Manage users, groups, permissions and processes.
- Administer system services and investigate system logs.
- Troubleshoot networking and connectivity issues.
- Understand storage, memory and system resource utilisation.
- Develop Bash scripting and operational automation skills.
- Build foundations for DevOps, cloud infrastructure and SRE.

## Learning Methodology

Each topic follows a practical learning cycle:

1. Understand the underlying concept.
2. Document key terminology and mental models.
3. Practise commands in a Linux environment.
4. Investigate real-world scenarios.
5. Document observations, results and troubleshooting steps.
6. Test understanding through exercises and assessments.

The emphasis is on understanding how Linux works rather than memorising commands.

## Learning Roadmap

- [ ] Linux architecture and fundamentals
- [ ] Shell and command-line proficiency
- [ ] Filesystem hierarchy and file management
- [ ] Users, groups and permissions
- [ ] Processes and resource management
- [ ] systemd and service administration
- [ ] Logging and troubleshooting
- [ ] Networking and connectivity
- [ ] Storage and performance
- [ ] Bash scripting and automation
- [ ] Linux security and SELinux
- [ ] Containers and infrastructure operations

## Lab Documentation

Every practical lab should include:

- **Objective:** What am I trying to achieve?
- **Environment:** Which system and user am I working with?
- **Commands:** What commands did I execute?
- **Expected results:** What should happen?
- **Observations:** What actually happened?
- **Troubleshooting:** What went wrong and why?
- **Key takeaways:** What did I learn?

## Guiding Principle

Understand the mechanism, not just the command.

The ultimate goal is to develop the ability to independently operate, troubleshoot, automate and maintain Linux systems in professional SRE / DevOps environments.
